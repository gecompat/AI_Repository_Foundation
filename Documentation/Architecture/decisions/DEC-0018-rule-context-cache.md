# DEC-0018 — Rule-context caching uses session analysis plus content-addressed local records

- Status: Accepted
- Date: 2026-09-01
- Context: Codex rebuilds its `AGENTS.override.md`/`AGENTS.md` instruction chain at the start of each run or TUI session. Foundation repositories also route agents to additional governance, architecture, validation, context, repo-map, schema, and decision sources. Repeatedly placing unchanged additional sources into model context and reanalyzing them during every implementation wave wastes tokens and time. Reusing an unvalidated summary or a `HEAD`-only fingerprint would instead risk missing dirty-working-tree changes, scoped overrides, moves, or transitive rule changes.
- Decision: Native instruction discovery remains mandatory on every new run. The Foundation cache contract uses a hybrid design: semantic analyses remain session-local and are addressed by deterministic per-source analysis keys; an optional non-versioned local record persists only repository/worktree/scope identity, exact instruction order, discovery configuration, working-tree and Git fingerprints, dependency edges, and self-integrity metadata. A hit requires exact validated logical content and topology. A non-instruction source change produces partial invalidation of that source and all transitive dependents. Instruction, scope, topology, source-set, contract, corruption, or uncertainty changes produce a full miss. UTF-8 LF/CRLF-only differences follow the existing portable-content policy. The optional reference capability provides a dependency-free `check`/`record` planner; caching itself is not a new rule authority.
- Rationale: Session-local analysis is the smallest store that saves repeated wave-level model work without persisting potentially sensitive semantic summaries. A content-addressed local record adds deterministic cross-checking and explainability while remaining cheap, disposable, and privacy-minimizing. Hashing actual working-tree bytes is inexpensive local work and is necessary to detect staged, unstaged, and untracked rules; Git commit identity alone is insufficient.
- Alternatives: A session-only record with no persistent fingerprints was rejected because it cannot reliably explain or compare later scopes/runs and offers no reusable deterministic implementation. Persisting rule text or semantic summaries was rejected because it creates a second sensitive content store and risks stale derived authority. Keying only by `HEAD` was rejected because dirty and untracked changes disappear. Timestamp/mtime caching was rejected as non-deterministic. Reimplementing or bypassing Codex's native run discovery was rejected because client instructions and configuration may change independently.
- Consequences: Foundation 1.8 adds `RULE_CONTEXT_CACHE_POLICY.md`, a v1 cache-record schema, an opt-in `rule-context-cache` capability, machine-readable contract metadata, deterministic reason codes, and regression coverage. Agents still read/honor system, developer, current user, and newly discovered instructions directly. Cache checks read source bytes for hashing but can avoid renewed model ingestion/semantic analysis. Cache records are local, atomically written, lock-protected, non-authoritative, non-evidence artifacts and contain no raw rule/analysis text or absolute host paths.
- Affected areas: agent instruction discovery, working-wave preflight, model/context cost, scoped governance, dirty-worktree handling, transfer manifest, feature catalog, schemas, validation, documentation, and optional capabilities.
- Supersedes: none.
