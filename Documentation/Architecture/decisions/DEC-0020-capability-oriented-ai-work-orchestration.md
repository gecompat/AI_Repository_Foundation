# DEC-0020 — AI work orchestration uses capability discovery and isolated optional execution

- Status: Accepted
- Date: 2026-09-07
- Context: Foundation 1.9 can choose a current model through a provider-neutral contract, but dependable AI-assisted work also uses deterministic tools, retrieval, rendering, validation, human review, local runtimes, hosted services, and clients with different permissions. Treating Ollama, MCP, Python, a model, an IDE, or any other component as mandatory would contradict the Foundation's vendor-neutral continuation goal. A generated adapter or healthy local service also cannot create authority to transmit data, spend money, mutate a repository, push, publish, or approve its own output.
- Decision: Introduce a runtime-neutral `foundation-ai-work/v1` control plane for capability discovery, planning, execution evidence, provisioning, and gap reporting. Keep Foundation policy and JSON contracts usable without an executable reference capability. Preserve `foundation-model-router/v1`; add a compatible v2 path for execution boundaries, per-provider health, provenance, and resource-aware selection without changing the canonical meaning of `LOCAL`. Use isolated provider catalog fragments and a language-neutral JSONL/stdio adapter protocol. Ship all invocation, orchestration, provisioning, client integration, and adapter synthesis only as explicitly selected optional capabilities. The executor intersects declared adapter needs with the caller's actual authorization envelope, applies privacy/capability/quality/resource constraints before economics, and uses risk-gated validation: reversible work may continue automatically, but irreversible effects, unapproved transfer/spend, high-impact conclusions, or insufficient evidence require an explicit authority checkpoint. Locally synthesized adapters remain outside the repository, receive no implicit rights, and must pass conformance checks before use; durable adoption still requires a separately authorized repository workflow.
- Rationale: A capability graph generalizes across software, research, documentation, data, media, and future work without turning a model or transport into the orchestration authority. Failure isolation keeps one unavailable component from disabling healthy alternatives. Separating the control plane, optional executor, and payload channel minimizes retained content and lets projects implement the contracts in any language. Explicit authorization intersection prevents discovery or code generation from becoming privilege escalation.
- Alternatives: extending the model router into a mandatory universal runtime was rejected because it would couple Foundation integrity to Python and provider behavior; treating local execution as a new meaning of `LOCAL` was rejected because it would break the established deterministic tier; shipping only Ollama adapters was rejected as vendor-specific; automatically accepting model-judged output was rejected because agreement is not validation; automatically committing synthesized adapters was rejected because many clients have no repository or remote authority.
- Consequences: The implementation is staged across `WI-0020` through `WI-0029`. Existing v1 users remain supported. New transferable policy and schemas are core; executable planners, adapters, executor, provisioner, and client helpers are opt-in. Concrete models, prices, endpoints, host measurements, credentials, payloads, and runtime traces remain target/runtime facts outside Foundation policy. Each stage must leave the ruleset functional when every optional component is absent. The Foundation source repository adopts the completed contracts as a target-facing self-hosting example without transferring its project-specific profile.
- Affected areas: model and resource routing, AI-assisted work planning, validation, authorization, privacy, dependency handling, runtime state, adapters, provisioning, client integration, schemas, transfer manifest, feature catalog, installer, tests, and cross-platform acceptance.
- Supersedes: none.
- Superseded by: none.
