# AI Repository Foundation v1.25.0

AI Repository Foundation gives human-maintained and AI-assisted repositories durable project instructions, clear authority, safe operating boundaries, stable artifact identities, validation contracts and a way to continue work without relying on a previous conversation or a particular AI provider.

This is the first published GitHub release. It brings the existing Foundation ruleset and reference tools together at a fixed version for software, research, education, documentation and other knowledge projects. The existing ruleset version is retained as `1.25.0`.

## What is included

- **Governance and continuity:** project context, rules, scoped discovery, privacy/authorization boundaries and factual handovers.
- **Installation and upgrades:** a manifest whitelist, complete semantic feature assessment, portable hashes and installation provenance. Existing project rules, identifiers, license and validation remain authoritative.
- **Identity and registration:** persistent machine UIDs, stable human references and a shared Registration Authority for people and AI.
- **Validation and efficiency:** separate integrity, project-semantic and runtime claims; local deterministic checks, scoped context, dependency-aware analysis reuse and bounded work.
- **Optional reference capabilities:** planning, model routing, runtime/client integration, execution, orchestration, host preparation and lifecycle support. These remain opt-in and require their own configuration, authority and evidence.

The [user guide](../Guides/USER_GUIDE.md) explains the complete feature/capability set and how to choose only what a project needs. The [architecture overview](../Architecture/OVERVIEW.md) explains components and responsibilities.

## What v1.25.0 adds

The documentation policy now requires understandable human reading paths, clear directory purposes, shared authoritative technical sources and separately discoverable AI control. README orientation and instructions remain separate from internal work logs, acceptance histories and AI handoffs.

New and materially changed paths must comply. Existing projects assess central paths at integration/upgrade and plan remaining legacy gaps with concrete scope, owner/role and trigger. Confusing layouts may need reorganization with their path consumers.

Documentation-impact assessment also applies when only behavior, APIs or configuration change. Local selection and dependency checks keep semantic inspection focused; unchanged analysis is reused only while actually available and valid. The rule introduces no recurring whole-corpus model audit, per-page metadata or new documentation validator. [Changelog](../../CHANGELOG.md) records the earlier ruleset development.

## Download and start

Download both attached assets:

- [Foundation ZIP](https://github.com/gecompat/AI_Repository_Foundation/releases/download/v1.25.0/ai-repository-foundation-1.25.0.zip)
- [SHA-256 checksum](https://github.com/gecompat/AI_Repository_Foundation/releases/download/v1.25.0/ai-repository-foundation-1.25.0.zip.sha256)

The reference installer requires Python 3.12 or newer. Installation from the Foundation ZIP does not require Git or an AI account. Verify the checksum, extract into empty staging, preview a core-only installation, and then apply the reviewed selection. Follow the complete [download and installation guide](../Guides/RELEASE_PACKAGE.md).

The attached Foundation ZIP is the manifest-whitelisted distribution. GitHub's automatic Source code archives are full repository snapshots. Optional capability sources are carried in the Foundation ZIP but remain disabled unless explicitly selected.

## Upgrading an existing project

Back up or commit project work, inspect the selected source version, preview changes and assess the applicable semantic feature delta. Resolve differing project files semantically; do not overwrite them to obtain a clean installation. Existing layouts can remain when they support clear reading paths. An upgrade with explicit planned legacy gaps does not establish full documentation conformity. See [existing-project integration](../Guides/USER_GUIDE.md#integrating-an-existing-repository).

## Validation and limits

This release covers the Foundation ruleset and deterministic reference tools. Release preparation checks source/registry consistency, cross-platform CI, reproducible packaging, checksum/index verification and installation from the actual release package. Exact source and artifact evidence accompany the published release.

Foundation integrity does not prove project-specific semantic correctness, understandable target documentation or runtime acceptance. Optional live-provider/client integrations need their own current host, model, capability, cost, security and authorization evidence. The reference adapters do not create an operating-system sandbox. The ZIP/checksum establish content integrity and provenance, not a publisher signature. See [known limitations](../Quality/KNOWN_LIMITATIONS.md).

Foundation's transferable material carries its namespaced MIT notice; the target project's root license stays independent. No target repository is upgraded by publication of this release.
